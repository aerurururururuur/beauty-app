# 参考图外部检索 · 可行性实测与选型（cn.bing.com）

> 对应 roadmap §5 与 §13-2。目的：验证「去外部真实找参考图」这条路在本机 /
> 部署环境下**能不能跑通、跑通后拿到的是不是有用的东西**。
> 原始数据都在本文，下一个读者不必重跑。
>
> 日期：2026-09-11 · 执行：本机（Windows 11），**全程不走代理**
> 相关：`ai-engine-api-spike.md`（上妆引擎选型，同目录）

---

## 0. 三句话结论

1. **可达性通过**：`cn.bing.com` 本机直连稳定（成功时段 p50 ≈ 200ms，连打 100 次 0 失败），
   无需 JS 渲染，图片无防盗链。Google / Pinterest **实测均不可达**。
2. **语义相关性的第一版实现是坏的**：部位名自己当检索词会漂移（`底妆` → 砂糖橘、`底妆 粉底` → 电击棍），
   且带上场合词会让 5 个部位**返回同一批图**。改用**具体品类词**后修复（见 §3）。
3. **授权问题一点没解决**：抓来的图落在知乎图床 / 摄图网（付费图库）/ 花瓣网 / 新浪图床 ——
   与抓 Pinterest 是同一类处境。§13-2 已记为「已知情变更」。

## 1. 连通性（本机，无代理）

| 站点 | 结果 |
| --- | --- |
| `cn.bing.com` | ✅ 200，页面 ~247KB |
| `www.bing.com` | ✅ 302 → `cn.bing.com`（中国版） |
| **Google** | ❌ `exit=35` TLS 握手被重置 |
| **Pinterest** | ❌ `exit=28` 12 秒超时，TCP 层被丢包 |
| 对照组 `baidu.com` | ✅ 200（排除「本机断网」） |
| 对照组 `api.open-meteo.com` | ✅ 400（项目已在用的接口） |

**是否需要 JS 渲染**：不需要。`murl` 全在原始 HTML 里，每页 ~25–35 条。
解析方式：`<a class="iusc" m="{…}">`，`m` 是 JSON 但内部 `"` 被转义成 `&quot;`。

**防盗链**：测过的源（知乎、摄图网、新浪）**不带 Referer、带浏览器 UA 都 200**，
magic number 是 `ff d8 ff e0`（JPEG）—— 即前端可以直接热链。

**限流**：连续 100 次请求 0 失败（p50 203ms / p90 261ms / max 308ms），未见 429/403。

### 1.1 ★ 但本机出站是**间歇性**的（重要）

同一进程内连打 100 次全成功，却会**成窗口地**整片连不上，特征是：

```
ConnectTimeoutError: Connect Timeout Error (attempted address: cn.bing.com:443, timeout=10000ms)
The operation was aborted due to timeout
```

- 实测撞到 3 次以上，每次持续几秒到一两分钟，**窗口过后立刻自愈**。
- 不是 Bing 限流：没有 429/403，且两个解析出的 IP（`202.89.233.100/101`）单独做 TCP connect 各 6 次全 OK（10–25ms）。
- 这导致 E2E 首跑 `references` 全空（任务仍 `done`，降级契约生效）。
- **应对**：给单次检索加了**一次重试**（`ATTEMPTS=2`，间隔 400ms）。
  代价 = 真断网时每个任务的检索阶段是 `2 × timeout + 400ms`，不是 `timeout`。

## 2. 语义相关性（**第一版实现是坏的**）

第一版检索词 = `「场合」+「部位」+「妆容」`（如 `面试 底妆 妆容`）。实测两个致命问题：

### 2.1 五组查询返回**完全相同**的图

`面试 底妆 妆容` / `面试 眉 妆容` / `面试 眼影 妆容` / `面试 颊 妆容` / `面试 唇 妆容`
五组各 35 条，**前 10 张两两 Jaccard = 1.00**（10 组两两全部相同）。

Bing 把查询**坍缩到了场合词**上。结果页返回的是「面试」场景图（知乎面试技巧、商务男士求职形象），
**不是妆容图**。这意味着「按部位分解」这个产品前提**直接没了** ——
结果会把同一张图贴五个不同的部位标签，比不给图更糟。

### 2.2 抽象部位词会漂移，且**不稳定**

| 查询词 | 第 1 轮 | 第 2 轮 |
| --- | --- | --- |
| `底妆` | 砂糖橘（1 条） | — |
| `粉底` | 电棍专卖（1 条） | — |
| `底妆 粉底` | 电击棍（1 条） | **大众汽车电子件**（35 条） |
| `foundation makeup` | 教学设备 | **"Numbers 1 to 3"** |
| `眼影 妆容` | 毛泽东画像壁纸 | — |
| `底妆 妆容` | 反洗钱（FATF）英文文件 | — |
| `底妆 教学` | 商务合同范本 | — |
| `眉 教学` | Funny Cat Memes | — |
| `唇 教学` | ZURU 招聘 | — |

**照抄的 `q` 不变，两轮结果可以完全不同** —— 这一条本身就说明这条路不能靠调词硬凑。

### 2.3 对照：解析器本身是对的

| 查询词 | 结果 |
| --- | --- |
| `猫` | 波斯猫摄影 ✅ |
| `夕阳` | 夕阳黄昏剪影 ✅ |
| `口红` | 口红排行榜 / 唇情动人 ✅ |

所以问题**不在解析、不在连通**，在 Bing 对这批中文抽象复合查询的相关性本身就不可靠。

## 3. 修复：用**具体品类词**，且**查询里不带场合词**

部位 → 品类词（见 `bing-reference-provider.ts` 的 `ROLE_QUERY`）：

```
底妆→粉底液   眉→眉毛   眼影→眼影   颊→腮红   唇→口红
```

实测两轮**都稳定且对题**：

| 查询词 | 结果 |
| --- | --- |
| `粉底液` | 香奈儿奢华精萃滋养粉底液 ✅ |
| `唇膏` | DIOR 魅惑润唇膏 ✅ |
| `眼影` | 眼影质地与粉质评测 / 6 种万能眼影画法 ✅ |
| `腮红` | 腮红画法看这一篇就够啦 ✅ |
| `眉毛` | 28 种眉毛类型详解 / 修眉毛教程 ✅ |
| `口红` | 口红排行榜前十名 ✅ |

修复后 E2E：**10 条参考、10 个互不相同的图片地址**，5 个部位各 2 张且各对题。
连跑 10 次任务：**10/10 成功，p50 956ms**。

**为什么查询不带场合词**：见 §2.1 —— 场合词一进来，部位分解立刻失效。
场合对参考图的影响**不再走检索词**；场合仍由 `scene-rules` 决定妆容方向（那部分没变）。
这是对产品设想里「场景 → 检索词」那一层的**主动放弃**，不是疏漏。

## 4. 代价（都是知情接受）

| 代价 | 说明 |
| --- | --- |
| **授权没解决** | 来源是知乎图床 / 摄图网（付费图库）/ 花瓣网 / 新浪图床。与抓 Pinterest 同类。主办「不得侵犯第三方知识产权」**仍适用于本模块** |
| **不是「妆容参考」** | 拿到的是**品类图 + 教程文章配图**（粉底液产品图、腮红画法文章封面），不是「某场合的妆面成品」。别把前者说成后者 |
| **`role` 不是视觉识别的结果** | 它是「哪个检索词搜出来的」。本项目没有视觉模型，无法真的看出「这张图在画唇」 |
| **热链** | 图片指回原站，没下载。源站失效 / 上防盗链就白图 |
| **出站抖动** | 见 §1.1，靠一次重试缓解，不是根治 |

## 5. 给下一个读者的提醒

- **别把 `role` 换回部位名当检索词** —— 那是本文 §2.2 实测过的错，测试里有回归保护。
- **别往查询里加场合词** —— §2.1 实测过，会让 5 个部位返回同一批图。
- **失败必须降级为空数组**：`jobs/run-pipeline.ts` 调 `referenceProvider.fetch` 时**没有 try/catch**，
  抛错会把整个上妆任务标成 failed。参考图是增强项，不是主链路。
- 想换站点（镜像 / 自建代理）：`REFERENCE_BASE_URL` 可配，不必改代码。
