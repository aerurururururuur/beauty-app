> 当前贴图的 alpha 在**算术上不可能盖住原生眉毛**。用户实测反馈是
> 「原生眉毛都还在，然后叠了一层眉毛」，也就是评判者看到的是**两层眉的差**，

> 所有数值仅作**重构前对照**，不得直接写进代码当最终值。见 §10、§11。

**一句话**：现在的眉毛不是"毛发算法不好"，是**四件不同的职责被压进了一个标量 `density`**——
外轮廓、边缘溶解、内部毛流、色调深浅共用一个 alpha，再过同一个单调压缩，
于是"边缘再自然一点"和"内部毛流多一点"必然互相牵制。解法是**分层**，不是调参。

### 0.2 ⚠️ 2026-09-14 修订：首要根因不是"画得不够真"，是**"盖不住"**

#### 0.2.1 用户实测（本文最高优先级的证据）

`[用户实测]` 在网页上生成效果后的一手反馈，原文：

> 「一看就是贴图，**原生眉毛都还在，然后叠了一层眉毛**」

这条把问题的性质说清楚了。评判者看到的**不是**"一层画得不够逼真的眉毛"，
而是**真实眉毛 + 叠加层，两层同时可见**。§1 那五条描述的都是叠加层自身的毛病，
在"两层眉"的语境下全部是**次生成因**。

#### 0.2.2 为什么盖不住：贴图的 alpha 在算术上做不到 `[实测]`

口径与 §2 一致（贴图体素，`i11005.png`，960×400）：

```
峰值 alpha        0.639        （硬顶，>0.64 的像素占 0.00%）
中位数            0.271
均值              0.298
>0.50 的像素      21.4%
>0.80 的像素       0.00%
>0.95 的像素       0.00%
```

眉体内部，**原生眉毛亮度透过 `1-alpha` 的比例**：

| 分位 | p10 | p25 | **p50** | p75 | p90 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 真眉透过 | 94.5% | 88.2% | **72.9%** | 52.9% | 40.4% |

**结论是纯算术的：即使取全眉最浓的 p90，仍有约 40% 的原生眉毛亮度透出来；
中位处透出 73%。** 这跟"真实度"无关——**这层妆在物理上就没有能力遮住下面那条眉**。

#### 0.2.3 根因：`peak` 的口径是**借来的，而且借错了品类** `[一手·本地代码]`

`scripts/make-brow-textures.py` 的 docstring（L85–88）与 `STYLES` 的注释（L271–273）
一致写着：

> **peak 就是上脸后的不透明度**。……参考贴图（blush 6417 / eyeshadow）的峰值量程是
> 90–163/255，写超过这个量程就不是"浓"，是一块不透明的颜料。

这条推理**在眼影/腮红上成立，在眉毛上不成立**：

| 品类 | 产品语义 | 正确的量程参照 |
| --- | --- | --- |
| 眼影 / 腮红 / 唇 | **薄涂显色**，要透出皮肤 | 参考贴图的 90–163/255 ✅ |
| 眉 | **覆盖 + 塑形**，要盖住原生毛发 | ❌ **不能拿眼影的量程当上限** |

于是 `peak` 被硬顶在 `0.64`（`shape-*` 三档）与 `0.42–0.56`（`fill-*` 三档），
**整个眉品类的上脸不透明度天花板上限就是 64%**。在这个上限下，无论 §4 那几个
结构问题修得多好，原生眉都会透出来。

> 这是**口径错误，不是调参问题**。§10「不修改参数」这条**不覆盖 `peak` 的语义**——
> 见 §10 的修订。

#### 0.2.4 引擎侧也没有任何补救 `[一手·本地代码]`

- **没有"眉部遮瑕"这一层。** `MakeupEngine.js` 里没有对原生眉做任何压暗/模糊/覆盖的
  处理；`loadBlurMat` 的 blur 网格 `visible = false`（L330），且用途是 warp/折射，与眉无关。
- **`_transparency` 无 UI 档位**——`materials.js:219` 硬编码 `1.0`，`src/` 内无任何写入点。
  也就是说即使用户想手动加浓，也没有入口。

#### 0.2.5 顺带发现的一条独立缺陷：无 mipmap 导致的高频走样 `[实测]`

`materials.js:201–203`（brow）与其它五个品类**写法一致**：

```js
xxTexture.minFilter = LinearFilter;
xxTexture.magFilter = LinearFilter;
xxTexture.generateMipmaps = false;
```

**同样的设置，对平滑品类无害，对眉是主动破坏：**

- 眼影/腮红/唇的参考贴图是**低频**的（§2.8 实测：17197「完全平滑，零高频细节，
  边缘 10%→90% 过渡 71px」）。平滑图做双线性缩小，得到的就是正确答案。
- 眉是**唯一带高频内容**的品类（单根毛特征宽 ~3.5px）。贴图按 **24.2 px/mm** 作画
  （眉带 725px ≈ 30mm），上脸按 §0.1 自己的口径是 **6 px/mm** —— 也就是**缩小 4 倍**
  （真实摄像头 3.5 px/mm 时缩 7 倍）。无 mipmap 的双线性缩小 4 倍 ≈ 每 16 个纹素采 4 个，
  **毛发细节不是被平均掉，是走样成颗粒**。

对照图（本仓库生成，可复看）：`tespro/_scale_compare.png`，
四种尺度 × 有无 mipmap 并排。**6 px/mm 那一格，无 mipmap 版是明显颗粒噪点，
有 mipmap 版是平滑柔和的色场。**

> `[口径]` 该对照图用**点采样**模拟"无 mipmap"。真实 GPU 双线性会在 1 个纹素范围内
> 做少量平均，所以实际表现比模拟**略好**，但远达不到面积平均的效果。方向可信，
> 数值不可当精确值引用。

**修法（一行级，独立于本重构）**：`generateMipmaps = true` +
`minFilter = LinearMipmapLinearFilter` + 按 `renderer.capabilities.getMaxAnisotropy()` 开各向异性
（眉带贴在弯曲的眉骨上、常以斜角被观察，各向异性过滤在这里收益明显）。
WebGL2 下 NPOT 纹理支持 mipmap，960×400 无兼容问题。

## 1. 目标

> ⚠️ **2026-09-14 修订后的层次**：下面是**次生**问题。**首要**问题是 §0.2 的"盖不住"，
> 它不在本表里，优先级高于全表。**先解决覆盖，再解决下面这些**——否则把下面五条
> 全修好，上脸仍然是"两层眉"，因为透出来的原生眉本身就不属于这五条中的任何一条。

本轮要解决（用户以"一眼能看出有处理痕迹"提出的五点，去掉范围外的一点）：

| # | 症状 | 归属 |
| --- | --- | --- |
| ① | 眉色太均匀，眉头到眉尾颜色变化很小 | 本重构 |
| ② | 眉毛边缘太干净，像笔刷描出来的 | 本重构 |
| ③ | 眉头尤其像一块连续的颜色 | 本重构 |
| ⑤ | 缺少毛流，看不到一根根眉毛 | 本重构 · **但见 §0.2.5 与 §9 的口径修订** |
| ④ | 左右对称度偏高 | **不在本重构**，见 §4.4 |

明确排除：**左右镜像属于 UV / shader 层问题，本次不在生成器里解决。**

### 1.1 这五条为什么不该单独作为重构目标

`[推测]`（结构性推断，未实测）在"两层眉"的实际观看条件下，这五条**每一条都被
底下那条真眉放大**：

| 症状 | 单独看（只有叠加层） | 叠加在真眉上看 |
| --- | --- | --- |
| ① 色调均匀 | 一层平的颜色 | 平的颜色 vs 真眉的深浅毛发 = **对比出"贴"** |
| ② 边缘干净 | 描出来的一条边 | 干净的边 **和真眉的毛丝边并存 = 两条边** |
| ③ 眉头成块 | 一块连续色 | 色块 **压在真眉的稀疏眉头毛上** |
| ⑤ 缺毛流 | 看不到一根根毛 | 真眉的毛 **从叠加层里透出来**，两层毛对不上 |
| ④ 左右对称 | 两边一样 | 真眉本就不对称，**对称的叠层更显突兀** |

**所以 §4 的四个结构根因依然成立、依然要修**，但它们解释的是"修完之后为什么仍然
不像真眉"，**不解释"为什么一眼就被认出来"**。后者是 §0.2。

### 2.4 脊线剖面 `[实测]`

眼睛读"眉色"读的是脊线（每列最大值），不是列均值：

```
t      0.15   0.25   0.35   0.45   0.55   0.65   0.75   0.82   0.90   0.96
脊线   0.400  0.608  0.635  0.639  0.639  0.635  0.635  0.627  0.608  0.533
```

**t=0.25→0.82（全长的 57%）脊线钉在 0.608–0.639，摆幅 5%。脊线 CV(t∈0.15–0.85) = 0.071。**

成因（`[一手·本地代码]`）：脊线上 density 从 1.15 涨到 2.4（**2.1×**），
过 `1-exp(-2.6·d)` 后 alpha 只从 0.95 走到 0.998（**1.05×**）。转移函数局部斜率：

```
d=0.3 → alpha 0.542  斜率 1.192
d=1.0 → alpha 0.926  斜率 0.193
d=1.5 → alpha 0.980  斜率 0.053
d=2.0 → alpha 0.994  斜率 0.014
```

**压缩发生在脊线，不在面积。** 这两件事必须分开说，混起来就是 §0.1 那个错误。

## 4. 根因

### 4.1 毛流承担了色调（对①②③⑤都有贡献）

`[实测]` 毛流占合计密度 **59–83%**，在整条横截面上都是主导项。
也就是说，今天真正在画"眉色"的是毛流层，底衬只是配角。

而毛流恰恰是**最不适合承担色调**的一层：它经过 p90 全局归一化（绝对量级被抹掉）、
经过 2520 次累加、再经过饱和的 `1-exp`。三重压缩之后，轴向包络的变化活不下来。

### 4.2 毛流在中央过度集中（对①⑤）

`[实测]` 毛流的中线/边缘比 **90×**，比底衬的 44× 更陡。

后果是**反直觉的**：毛流最密的地方恰好是它最看不见的地方。
中线毛流密度 1.48 → 过 `1-exp(-2.6·1.78)` = 0.990，饱和成平滑场；
两翼密度 0.2 → 一根根分得开。

**§2.5 的 0.79 vs 2.99 就是这么来的。**

### 4.3 单一 alpha 承担多个职责（对②③）

两层含义：

**(a) 毛被 base 裁掉，没有边界权。**
`hair_density(...) * base` 把每根毛关进眉形内。毛画完再乘一次羽化后的眉形，
等于从毛的中段软切一刀——**尖端锥度没了**，留下一道与轮廓平行的衰减。

**(b) `cross_fall` 在轮廓处恰好为 0。**
`d = min(y-y0, y1-y)/半高`，在多边形边缘 `d=0` ⇒ `d^1.6=0`。
所以 alpha 的等值线是一族与轮廓平行的**解析曲线**，数学上不可能有高频。
`[实测]` 下缘 alpha 恒为 **0.000**，上缘 0.006 且非零仅占 12%，正是这个。

**(c) 眉头三机制叠加。**
几何最厚（117–118px，1.38×）+ `length_env` 把毛长砍到 45%
+ `axial_envelope` 右侧在 t=1 仍保留 0.475 + 落点向中心聚集
⇒ **大面积 + 中等密度 + 最短的毛** = 一块中间调。

### 4.4 左右 UV 镜像（对④，**不在本重构解决**）

`[一手·本地代码] [实测]` §2.1 已证明：19/19 镜像配对，Δu ≤ 8.4e-5。
**两只眉毛在像素级上互为镜像，不存在任何差异。**

这不是"生成器随机性不够"，是 UV 布局决定的。
**在贴图里画任何左右不对称，都会同步镜像到另一侧。**
只能靠 shader 的每侧 UV 变换，或换 UV 布局。**不要为了修④把整个生成器推倒。**

## 5. 数据模型

**`density` 这个词退役**——它同时指四样东西，本身就是 bug 源。

| 符号 | 名称 | 语义 | 性质 |
| --- | --- | --- | --- |
| **B** | Brow Envelope | 眉毛整体形状 | 光滑、低频、连续场 ∈[0,1] |
| **H** | Hair Coverage | **由离散毛发产生的覆盖** | 见下 |
| **A** | Final Alpha | 最终透明度 | 屏幕不透明度，直达画面 |

### 5.1 H 的语义（工程上必须分清）

**"离散"是语义，不是存储形式。** 实现上最终仍需要一个栅格结果 `H(x,y)` 才能合成。
这条链路必须在文档和代码里都写清楚，否则实现者会误解：

```
Hair Field / Hair Set        ← 逐根毛发的几何：根 / 方向 / 长度 / 粗细 / 自身不透明度
        │
        │  rasterize
        ▼
Hair Coverage  H(x,y)        ← 由离散毛发**产生**的覆盖场
```

**H 的语义是"由离散毛发产生的覆盖"，不是"H 在计算机里永远不能表现成一个场"。**

### 5.2 B 的语义

**B 不是"剪刀"，是"生长许可场"。**
今天的 `hair × base` 让 B 成了裁剪器；新的 B 只回答
"这里允不允许长毛、允许多少"，**不直接砍毛**。

## 6. 分层管线（L1–L4）

```
┌─ L1  Envelope ───────────────────────────────────────────┐
│   实测关键点 → 样条 → 轮廓 → 轴向包络 × 横截面包络        │
│   产出 B(x,y) ∈[0,1]    光滑、低频                        │
│   职责：整体形状 + 色调                                    │
└──────────────────────┬───────────────────────────────────┘
                       │  B 作为「生长许可场」
                       ▼
┌─ L2  Hair Field ─────────────────────────────────────────┐
│   根位置 R(x,y)  ← 从 B 采样，但 R ≠ B                    │
│   产出逐根毛发的几何（§5.1 的 Hair Set）                   │
│   职责：毛根在哪、朝哪、多长、多粗                          │
└──────────────────────┬───────────────────────────────────┘

┌─ L3  Hair Edge ──────────────────────────────────────────┐
│   按根位置分两群：                                          │
│     主体毛 —— 尖端在**生成时**截到 B 等值线内               │
│     边界毛 —— 允许有限越界 over ∈ [0, δ]                   │
│   职责：毛尖决定局部边缘的高频扰动                          │
└──────────────────────┬───────────────────────────────────┘
                       │  rasterize → H(x,y)
                       ▼
┌─ L4  Composition ────────────────────────────────────────┐
│   A = 1 - (1 - A_B)(1 - A_H)                             │

└──────────────────────────────────────────────────────────┘
```

## 7. 合成公式

### 7.1 主公式

```
A = 1 - (1 - A_B) · (1 - A_H)

  A_B = p_B · B(x,y)                        ← 线性
  A_H = 1 - Π_i ( 1 - a_i · s_i(x,y) )      ← 透射率（保留"重叠变深"）

  s_i  第 i 根毛的笔画覆盖 ∈[0,1]
  a_i  该根毛自身的不透明度 ∈(0,1]，**逐根不同**
```

**为什么必须是两条支路**：今天 `density = B项 + H项` 之后过 `1-exp(-K·density)`，
四条职责压进一个标量再压一次。分成两条支路后：

- "边缘再自然一点" → 只动 L3 的边界毛群，不影响 L1/L2
- "内部毛流多一点" → 只动 L2 的采样，不影响 L1/L3

### 7.2 A_B 线性是治①的关键

脊线亮度 = `p_B · B(脊线)`，**直接跟随轴向包络**。
今天脊线密度 2.1× 的变化过 exp 只剩 1.05×；线性之后同样的 2.1× 就是 2.1×。

### 7.3 墨量重新分配（不是删毛）

`[实测]` 今天 4200 根 σ=0.95 软笔刷的累加，实际在干**两件事**：

| 现在 H 在干的事 | 应该归谁 |
| --- | --- |
| 让眉体读起来是**实体** | → **A_B**（平滑、线性、便宜） |
| 让眉体读起来有**一根根毛** | → **A_H**（小、硬、可分辨） |

**把那部分墨从 H 搬回 B，总墨量可以不变。** 现在毛流占合计密度 59–83%（§2.3），
重构后应该反过来——B 是色调主体，H 是纹理。

> **这条直接回答"覆盖率要不要从 3.87× 砍下来"：不需要暴力砍。**
> 先解决 §4.3 的结构问题，再决定覆盖率。否则很容易为了看见毛，把眉毛做成"稀疏假毛"。

### 7.4 边界权分级（L3）

```
主体毛  根在 B > τ_root 内
        毛尖在**生成时**截到 B = τ_tip 等值线以内
        ⇒ 不是画完再乘 B。生成时定长，毛尖保持完整锥度，只是停在里面

边界毛  根在 B 的边界带内，允许有限越界 over ∈ [0, δ]
        比例小、长度短
```

**为什么必须分级**：如果所有毛尖都拥有同样的边界权，会从 `████████`
直接变成 `/////\/\/\/`，又回到"边缘毛糙、像噪声"。

```
结果：期望边界 = B 的等值线（干净、稳定）
      实际边界 = 等值线 ± 小幅高频抖动
```

### 7.5 根分布的三条约束（L2）

```
约束1  R ≠ B。R 管"毛长在哪"，B 管"底色多深"，两者解耦
约束2  R 的横截面分布必须比现在**平坦**
       （现在中线/边缘 = 90×，§2.3）
       否则脊线永远过饱和、两翼永远没毛
约束3  R 沿长轴仍受轴向包络调制（眉尾稀、眉头稀）
```

**眉头（③）不需要特判**，从结构里自然出来：几何轮廓保持厚，
但 `A_B(眉头)` 和 `R(眉头)` 都降低 ⇒ 读作"一块稀疏、透皮肤、有几根朝上短毛的区域"。

## 8. 不变量

必须保持，任何实现不得违反：

1. **B 不负责裁剪毛尖。**
   B 是生长许可场，不是剪刀。毛的长度在 L2/L3 生成时确定，
   **不得**在合成阶段对毛发乘以 B 来裁。

2. **`A_H` 在眉体中段不得贴到 1。**
   否则 `1-(1-A_B)(1-1) = 1`，B 的轴向变化被合成环节抹平——
   和今天的 `1-exp` 饱和是同一个病，只是换了地方。

   **不应该预先规定真实眉毛有多少根，而应该规定：**
   **毛发层必须保留足够的动态范围，使底层 envelope 的变化仍然能够影响最终视觉结果。**
   这才是可迭代的工程约束。

3. **毛发独立于最终 base alpha。**
   L2/L3 的产出不得依赖 L4 的合成结果。

4. **左右镜像问题暂不在 generator 解决。**
   见 §4.4。在任何情况下都不允许"在贴图里画左右不对称"来试图修④。

### 11.3 §8-2 的解卡：那是**设计决策**，不是实证闸门

原文把 §8-2 写成「验证 `A_H < 1` 在实现层**能否真正保证**」并列为主流程的**前置阻塞**。
**这条卡点是假的**，两个理由：

**(a) 顺序错了。** "实现层能否保证某性质"没法在实现之前验证。它是**设计时**要写进
公式里的约束，不是**实现后**要跑的检验。把它当闸门，等于要求先有代码才能写代码。

**(b) 而且 `A_H < 1` 这个约束本身太弱。** 看 §7.1 的合成：

```
A = 1 - (1 - A_B)(1 - A_H)  =  A_B + A_H - A_B · A_H
                              ∂A/∂A_B = 1 - A_H        ← A_B 的灵敏度
```

**若 `A_H` 恒为 0.75（远小于 1，满足"不贴到 1"），A_B 的灵敏度就只剩 0.25**——
B 的轴向变化被衰减到四分之一。**"A_H < 1" 拦不住这件事。**

**正确的约束是：`A_H` 不得主导合成。** 即 `1 - A_H` 必须保持在一个下界之上。

**可解，且按构造成立**：给 A_H 一条**有界传递**，而不是裸透射率：

```
A_H = K_H · (1 - exp(-H / H0))        →  A_H ≤ K_H < 1，按构造
断言：assert A_H.max() <= K_H
灵敏度下界：∂A/∂A_B = 1 - A_H ≥ 1 - K_H
```

取 `K_H = 0.55` 则 A_B 的灵敏度全程 ≥ 0.45。**K_H 是设计参数，不是调参参数**——
它回答的是"毛发层最多占多少视觉份额"，属于 §5 数据模型的语义，**应当在写代码前定死**。

> 这条同时修正了 §8-2 的措辞：不变量应写成
> **「`A_H.max() ≤ K_H`，且 `K_H` 使 `1-K_H` 达到目标灵敏度下界」**，
> 而不是「`A_H` 不贴到 1」。前者可断言，后者不可。

### 11.4 症状 ④ 与 §0.2 的关系（供 §11.2 立项时参考）

的左右两半落在 UV 空间中互不重叠的区域**（实测 lm33 `u=0.5520` vs lm263 `u=0.6807`），

**在 canonical UV 下，左右不对称是可以在生成器里画出来的，不需要 shader 每侧变换。**

### 13.1 为什么做这个

（303×303）上量到的三个数：左眉 bbox 48×10 px、眉/皮肤分离 ≈44 灰阶、
同法量错位置（头发）时 191。

**那个判断是在 303px 抓图上量的**，而本项目的输入是**照片**（`roadmap.md` L328
上传→生成、L207 画到照片像素），正常自拍里眉宽 150–250px。
**303px 上定的案不构成对照片管线的否决** —— 所以重估，不是推翻。

本实验**不做实现，只做闸门**：在同一套口径下并排量三条 matte 路线，
判定「取原生眉再改」这条路值不值得往下投。

### 13.3 三条路并排 `[实测]`

操作统一为「按 alpha 加深」`I' = I·(1 − 0.55·α)`，即 `eyebrow_deepen` 的类比。

| matte 方法 | 边界软度 px | 眉芯 alpha | 眉内加深 | 皮肤污染 | alpha>.9 |
| --- | --- | --- | --- | --- | --- |
| ① 二值阈值（**现状**） | **0.00** | 1.000 | 0.1831 | 0.0000 | 100.0% |
| ② 线性解混 | 16.94 | 0.758 | 0.1358 | 0.0120 | 5.0% |
| ③ **closed-form**（Levin 2006） | **11.10** | **0.886** | 0.1598 | 0.0122 | 24.6% |

- **边界软度**：穿过边界 alpha 10%→90% 用了几 px。① 恒为 **0.00 px** ——
  **这就是它看着像贴纸的地方**；而「皮肤污染」**量不到这个**，它只量 matte **外**。
- **眉芯 alpha**：眉芯平均不透明度，「盖得住」的直接量。
- **皮肤污染**：matte 外 8px 环带被同一操作改动了多少灰阶。

**读数：③ 是唯一两头都占的。** ② 把边界做软了，代价是眉芯 alpha 只有 0.758 ——
它是靠**整体压低不透明度**换来的软，等于没盖住，不是真的定位准。
③ 边界 11.10px + 眉芯 alpha 0.886 同时拿到。

> `[口径]` ① 的「皮肤污染 0.0000」是**平凡**的：硬边 matte 在边界外不改任何像素，
> 是定义使然，不是优点。它的成本在边界上，而污染指标只量边界外。

### 13.4 §1065 的两个观察：一个复现、一个需要拆开

**(a) 「分离度不具判别力」—— 复现 ✅**

| 块 | 离肤色（0–1） | 灰阶 |
| --- | --- | --- |
| 眉 | 0.254 | **65** |
| 额中纯皮肤（对照，应≈0） | 0.021 | 5 |
| 发际线头发（对照） | **0.474** | **121** |

**头发那块的分比眉还大。** 所以**「分离度高」本身证明不了「这是眉」** ——
区分眉和头发靠的是**形状/位置**（列高短、左右成对），不是暗度。
这正是 §1065 那句「分离度对窗口位置极度敏感（44 vs 191）」的机制，
本节在**另一张图**上独立复现了它（65 vs 121）。

**(b) 「对窗口位置极度敏感」—— 需要拆成两件事 ⚠️**

§1065 的措辞把两件事并成了一句，本节把它们分开量：

| 窗口平移 | IoU（找出来的还是不是同一块眉） | 落回基线外的像素 |
| --- | --- | --- |
| y−4 / y−2 / y+2 / y+4 | 0.94 / 0.96 / 0.87 / 0.93 | 14 / 8 / 71 / 0 |
| x−6 / x+6 | 0.95 / 0.78 | 0 / 62 |

**IoU 0.78–0.96：窗口定位本身是稳的**，平移 ±4px 找到的仍是同一块眉。
§1065 的「极敏感」说的是**数字**会随落在哪个结构上剧变（眉 65 / 头发 121），
**不是**窗口稍微动一下就找不到眉。两句都成立，但混在一起会得出过强的结论。

> `[踩过的坑]` 这个检验**不能**用「平移窗口后重新算分离度」：那样 mask 也跟着平移、
> 永远只选到"暗的"像素，指标自我归一化，结果必然 ≈0。本实验第一版就这么量出过一个
> 假的「不敏感」（全列 −0%~+2%）。要问的是「换个窗口去找，**找出来的还是不是同一块眉**」。

> `[踩过的坑]` closed-form 的「确定前景」**不能拿整块二值 mask 当约束** ——
> 那块里有毛与毛之间的皮肤，钉成 alpha=1 是错的；更要命的是指标也在同一块上量，
> 读出来恒等于 1，是**循环论证**。第一版就这么写，③ 的「眉芯 alpha 1.000」是假的。
> 改为「眉区最暗的 35% 分位再腐蚀」后，读数才变成有意义的 0.886。

> `[踩过的坑]` 阈值的肤色基准**必须先排除近白背景**。该图背景是纯白，
> p75 = 254 → 阈值 183 → 全脸（含头发、眼睛、嘴）都算"暗"。第一版据此找不到眉。

### 13.5 判定

| 问题 | 判定 | 依据 |
| --- | --- | --- |
| **增强这条路**（局部加深/提对比/原生眉区塑形） | **闸门通过** ✅ | closed-form matte 边界 11.10px + 眉芯 alpha 0.886，明显优于现状二值的 0.00px |
| **换眉形这条路**（拿原生眉驱动一个**新形状**） | **本实验不能判定** ⚠️ | 303px 上眉只有 41×15 px；§1065 的「分辨率不够」是**按比例**的论证，**必须在真实照片分辨率上重测** |
| §1065「只够做增强」 | **不反对，但措辞要改** | 本节支持「增强够用」；「不够换眉形」是**分辨率依赖**的，不能在 303px 上定案 |

**架构上落到的位置**：路由**按原生眉密度**分流 ——

- **有眉（浓密）** → 取原生眉做 matte → 增强/塑形。**这正是本节验证的这条路。**
- **无眉/极稀（化疗后、天生稀疏）** → 合成。生成器 `fill-*` 三档现在就是干这个的。

这与美图**三条并列路**的观察一致（`meitu-makeup-tech.md` §5.1：
`eyebrow` 贴图替换 / `eyebrow_deepen` 原生眉区增强 / 云端去眉 `mtxxAINoEyebrow`），
且**不需要云端去眉** —— `photo-not-realtime` 决定的。

**本次没有做的事**（别当成做了）：没有接进引擎，没有改 shader，没有改纹理生成器。
`brow-composite-experiment.py` 今天用的仍是**二值** mask（①），本实验说明它应该换成 ③。
