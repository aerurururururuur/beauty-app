# `__fixtures__/` —— 录下来的生图请求/响应(当前**是空的**)

这个目录按 `MAKEUP_FIXTURES_DIR` 指向的形态存在,**现在还没有任何夹具**。

## 为什么是空的

录一份夹具要**真花钱**调一次百炼(`MAKEUP_ENGINE=image` + `MAKEUP_FIXTURES_DIR` 指向这里),
**这一步还没跑**。所以:

> ⚠️ **阶段 1 那条验收(「引擎离线可验」)目前只满足一半。**
> `buildPrompt` 的硬断言已经绿了(见 `test/makeup-prompt.test.ts`),
> 但**离线跑通一次真实出图**这一半**还没有证据**。

别把这个目录的存在读成"回放能跑了"。`ReplayEngine` 未命中时会**明确炸**,
不会静默返回假图 —— 所以它现在跑起来只会告诉你"没录过这一条",那是**正确行为**。

## 怎么录

```bash
# 1. .env 里填 DASHSCOPE_API_KEY,并设:
#    MAKEUP_ENGINE=image
#    MAKEUP_FIXTURES_DIR=<这个目录的绝对路径>
# 2. 用**真实输入**跑一次出图(照片字节、妆面单、肤色都要跟以后回放时一致)
# 3. 跑完这里会多出 <key>.json + <key>.png 两份
```

## 夹具里有什么

- `<key>.json` —— 请求全文(模型/提示词/参数/输入摘要)+ 响应元信息(图片文件名/字节数/`request_id`)。
- `<key>.png` —— 结果图本体(`.json` 里**不存 base64**,几 MB 的串会让夹具没法读、没法 diff)。
- `key` = `{templateVersion, model, prompt, negativePrompt, parameters, 输入摘要}` 的 sha256 前 16 位。
  **刻意排除了本机路径** —— 否则换个目录、换台机器,夹具就"找不到"了。

## 两条必须记住的话

1. **夹具绿 ≠ 线上绿。** 命中只证明"这次组装与录像时逐位相同",**不证明平台方还会这么画**。
2. **`TEMPLATE_VERSION` 一改,历史夹具全部失效**(回放会报"模板已变,请重录")。
   这是**有意**的:措辞变了还拿老图当证据,那才是真的骗人。改措辞要连同重录一起做。
